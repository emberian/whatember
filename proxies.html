03A · Merkleization Architecture

Four Complementary Merkleization Engines for Agent Proxies

A production agent proxy cannot use a single naive Merkle tree for everything: append-only turn transcripts, mutable key-value sandbox heaps, sparse revocation sets, and multi-agent fork trees have fundamentally different update and proof patterns. Our stack separates them into four specialized engines that weld into a single turn receipt.

Engine 1 · Availability & EquivocationZero-Dep Rust

1. Append-Only BLAKE3 MMR Proxy (`inclusion-availability`)

In degg-research/experiments/inclusion-availability/src/{mmr.rs,log.rs,equivocation.rs}, every admitted agent turn emits an InclusionReceipt over a BLAKE3 Merkle Mountain Range with domain-separated leaf (`0x00`), parent (`0x01`), and right-to-left peak bagging (`0x02`) hashes.

Crucially, verify_receipt derives the leaf’s 0-based position purely from the left/right bit-geometry of the sibling path—preventing an operator from lying about turn ordering—while verify_equivocation proves split-view proxy forks whenever two receipts at the same size disagree or violate prefix consistency.

Path: degg-research/experiments/inclusion-availability/
Engine 2 · Turn Transcript MMRSlot 3 · Lean 4

2. Wasm `grain-turn` History MMR (`HISTORY_ROOT_SLOT = 3`)

In breadstuffs/grain-turn/src/lib.rs, every Wasm agent turn commits the prefix of all prior turn digests $0 \dots N-1$ into HISTORY_ROOT_SLOT = 3 (breaking the circularity of hashing turn $N$’s own STARK receipt inside turn $N$).

Paired with breadstuffs/crates/dregg-query and metatheory/HistoryIndex.lean (server_cannot_omit), any counterparty can request a range of agent turns $[lo, hi]$ and verify via a RangeCertificate that the proxy did not drop a single intermediate tool call or refusal.

Path: breadstuffs/grain-turn/src/lib.rs · metatheory/HistoryIndex.lean
Engine 3 · Mutable Sandbox StateSlot 6 · $O(1)$ Forking

3. Sorted Poseidon2 Key-Value Heap & $O(1)$ Multi-Agent Forking (`HEAP_ROOT_SLOT = 6`)

In breadstuffs/cell/src/lib.rs and metatheory/Dregg2/Substrate/Heap.lean, the agent’s persistent memory is a sorted key-value store committed into a Poseidon2 Merkle root in HEAP_ROOT_SLOT = 6. Non-existence of a key is proven via adjacent-key gap witnesses (get_none_of_gap).

Because the entire agent state is captured by `(HEAP_ROOT_SLOT, HISTORY_ROOT_SLOT)`, breadstuffs/grain-fork/src/lib.rs implements $O(1)$ copy-on-write agent branching (`fork`), deterministic time-travel (`rewind`), and verified child-turn stitching (`absorb` / `stitch_child`), while confined-swarm proves non-collusion across parallel subagents.

Path: breadstuffs/grain-fork/src/lib.rs · metatheory/Dregg2/Substrate/Heap.lean
Engine 4 · Policy & RevocationDepth-16 4-Ary SMT

4. 4-Ary Sparse Merkle FactSet & 120-Felt Capability Forest (`commit` + `FullForestAuth.lean`)

In breadstuffs/commit/src/, policy facts and revocation lists are stored in a depth-16 4-ary Poseidon2 Sparse Merkle Tree (`FactSet`) supporting compact membership and non-membership proofs (`BudgetProof`, `LastUseProof`).

In metatheory/Dregg2/Exec/FullForestAuth.lean, multi-hop capability delegation chains are authenticated inside the STARK circuit as a 120-felt witness bundle (depth-12 forest), with gateOK_revoked_fails and minidregg/Theory/AcceptedCellEffectWitness.lean:no_accepted_of_stalePreRoot proving that revoked capabilities or stale pre-state roots cannot produce an accepted turn.

Path: breadstuffs/commit/ · metatheory/Dregg2/Exec/FullForestAuth.lean

03B · Capability & Keyless Gateways

Intercepting Tool Gateways, ACP Confinement & Keyless BYOK Proxies

When an autonomous agent calls external tools or upstream LLM APIs (Anthropic, OpenAI, AWS Bedrock), the proxy must enforce two invariants: (1) the agent can only invoke tools authorized by an attenuated capability chain, and (2) the agent never holds raw API keys in its own memory space.

C-ABI Lean Gate`DelegAdmit.lean`

`sdk::tool_gateway` & `dregg_deleg_admit`

In breadstuffs/sdk/src/tool_gateway.rs, every tool call (`invoke` or non-blocking routed promise `enqueue`/`resolve`) passes through @[export dregg_deleg_admit] compiled directly from metatheory/Dregg2/Apps/DelegAdmit.lean—replacing handwritten Rust boolean checks with a Lean-verified 6-way capability attenuation check and monotonic call counter (`CALLS_MADE_SLOT`).

ACP Proxy`deos-hermes`

`deos-hermes` & `dreggnet-hermes` ACP Gateway

Intercepts Agent Communication Protocol (`ACP`) tool calls (`ToolKind`, `ToolCallRequest`), binding every permission outcome (`PermissionOutcome`) to an 8-lane Poseidon2 `attestation_commitment` over the `ZkOracleAttestation` and hardware `TeeFactVerifier`.

Keyless BYOK`SO_PEERCRED`

`mini-keys`, `oracle-llm-proxy` & `keyless-grain-proxy.py`

In minidregg/native/mini-keys/src/, the proxy authenticates local agent processes via kernel `SO_PEERCRED` / `getpeereid` (`peer.rs`), checks `POLLIN` lease liveness (`caller_gone`), and injects encrypted BYOK credentials only inside the outbound TLS socket—proving `NoKeyMaterialInGrainMemory`.

03C · Verifiable External I/O

`zkoracle-live`: TLSNotary MPC-TLS Welded to Dyck JSON & DFA STARKs

What happens when an agent proxies an outbound HTTPS call to an external API (`api.anthropic.com`, `bedrock-runtime`, or a financial data feed) and needs to prove to a downstream counterparty that the response came from that exact TLS origin and satisfied a structural JSON policy—without revealing the API key or redacted fields?

MPC-TLS + STARK`zkoracle-live`

2-PC Garbled-Circuit AES-GCM + Selective Redaction

In breadstuffs/crates/zkoracle-live, the proxy runs a 2-party TLSNotary session where the verifier holds a garbled-circuit share of the TLS 1.3 AES-GCM session key. The HTTP Authorization header is zeroed in the committed transcript while the response body is committed into an 8-lane Poseidon2 sponge.

Welded Automaton`AttestedAutomatonWeld8.lean`

Zero-Extra-Column JSON & Policy Welding

Rather than hashing the TLS transcript in one circuit and re-parsing JSON in another, AttestedAutomatonWeld8.lean welds the Dyck JSON / DFA state transition directly into the rate-8 Poseidon2 absorption row—binding the TLS notary signature, the Poseidon2 transcript digest, and the JSON schema/policy verdict into a single `ATTESTATION_SLOT = 8` commitment.

03D · Verified Proxy Dataplane

`Orb`: 312-Module Lean 4 HTTP Proxy Lowered via HOL4/CakeML to 1,868 Bytes of x86-64

Even the strongest cryptographic receipt can be undermined if the HTTP proxy dataplane parsing the wire bytes suffers from buffer overflows, request smuggling, or circuit-breaker state bugs. We built and verified the proxy dataplane itself (`Orb`) across Lean 4 and HOL4/CakeML/Pancake.
