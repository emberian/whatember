  3. The bake-off is dated 09-29 (run) / 09-30 (verdict), and Mini did not "win" outright. Neither tree passed: Bread failed J5/J6/J8 (kernel semantics); Mini failed growth (storage/recovery). 2.1 What it is

Naming triad (DreggNet/memory/dregg-sel4-deos-firmament.md): robigalia the project, dregg the verified distributed object-capability kernel, deos the agentic desktop user layer ("dregg made visual; a window IS a Capability{Target::Surface(cell), rights}").

The firmament thesis (docs/FIRMAMENT.md, 494 lines; sel4/dregg-firmament/): an seL4 capability and a dregg capability are the same abstraction at different points of a distance parameter n; n=1 collapses distributed bounds to strong-local ones. Proved in metatheory/Dregg2/Firmament/{SeL4Abstract,CapGradation,SeL4Kernel,SeL4Composition}.lean, keystone dregg_turn_in_pd_preserves_both (a dregg delegation embedded as an seL4 mint preserves both the derivation-tree invariant and cap non-amplification). 1.1 The Core Kernel & State Transition Engine

The core operational kernel of breadstuffs lived across three tightly coupled layers:

1.2 Circuit-Emit, Architectural Law #1, and Rotated Layout Single-Source

Architectural Law #1: Zero Rust-Authored Constraints

As documented in metatheory/README.md:15 and docs/CIRCUITS-FROM-PROOFS.md:

*"Circuits are emitted from Lean (architectural law #1: zero Rust-authored constraints or AIRs, ever). Every constraint set the prover enforces is a byte-pinned artifact emitted from a proved Lean module (the Argus IR and the descriptor JSONs); Rust only interprets those artifacts. A coverage gap is closed by emitting from a new proved module, never by hand-authoring a constraint."*

The soundness boundary is absolute: a STARK verifier accepts exactly what the polynomial constraint system admits. A bug in a Rust witness generator causes a proof generation failure (a liveness bug). But a bug or omission in a constraint causes the verifier to accept invalid transitions (a catastrophic soundness break). This was proven painfully when predicate-arith.json was briefly hand-edited on disk, inadvertently omitting both Poseidon2 weld legs.

The Dual-Rung Verification Ladder

Every circuit family in metatheory/Dregg2/Circuit/Emit/ was required to climb two rungs:

2.1 Why Handwritten Rust AIRs Were Banned (Law #1)

The ban on handwritten Rust constraints was born from a fundamental asymmetry:

  • Witness generators are allowed to be buggy in Rust. A faulty witness generator produces inputs that fail to satisfy the verifier's polynomials. The proof fails to verify; the system halts or retries. This is a liveness defect.
  • Constraint systems must never be written in Rust. A missing or broken constraint changes the relation the verifier accepts. An adversary can forge invalid transitions that pass verification. This is a catastrophic soundness collapse. By forcing constraints to be emitted as data from Lean 4 (EffectVmDescriptor2), every accepted transition was anchored to a Lean refinement proof (turnChain_descriptor_refines_rust_air).

3.2 Lessons Learned in the Transition

1. Why Rigid Monolithic Shells Failed

  • The Build Lock Nightmare: In July 2026, local developer iteration ground to a halt because compiling starbridge-v2 locked the entire target directory. Building the desktop cockpit pulled GPUI, Alacritty, Servo, SpiderMonkey, Matrix SDK, and the Lean kernel archive (libdregg_lean.a), resulting in a 292MB binary that took minutes to link and frequently jammed (reference-persvati-remote-build).
  • Duplicate Dependency Crises: Direct dependencies collided with nested dependencies (e.g. workspace GPUI adb902652 vs gpui-component's internal 54fbcb6943), requiring complex workspace overrides.
  • Immediate-Mode UI Re-execution Overhead: Commit f27fd4169 documented that the cockpit repainted carded surfaces as frozen snapshots every frame, BLAKE3-hashing the entire state root on every render tick because projection memoization had not been integrated.
  • The Autonomous Swarm Failure: In ~/.claude/projects/-Users-ember-dev-delvetalk/memory/ember-working-style.md:21:

*"Three hours of autonomous codex produced 45 commits and a 124K-line repo ember called 'horseshit' and 'chug'; the failure was orchestration and refusal to subtract, not effort."*

The remedy was radical subtraction: separate the data models, drop monolithic GUI frameworks, and deliver user agency through lightweight, composable surfaces.

2. Why GPUI Cockpit Builds Needed Discipline

  • Monolithic cockpits must not bundle full editor workspaces, full web browsers, and full chat servers into the primary binary. The split pioneered by deos-view (declarative ViewNode tree) and obend-gui (HTTP/WebSocket server streaming interactive SVG/HTML viewports) demonstrated that rendering belongs at the edge, while state remains pure, verifiable data.

3. How Sandstorm .spk Grains Evolved

  • Sandstorm proved the elegance of capability-secured application grains with private /var heaps. However, Sandstorm grains lacked decentralized, light-client witnessability—users had to trust the central Sandstorm supervisor.
  • In DeOS, grains became content-addressed sovereign cells with verifiable umem heaps. In minidregg and delvetalk2, this evolved into sovereign objects where state transitions are mathematically checked against a plain-words law and recorded on an AT Protocol or blocklace journal.

6. Conclusion: The Return of the Living Image

The tragedy of the original DeOS effort in breadstuffs was not an error of vision; it was an error of packaging and mass. By attempting to construct the compiler, the proof system, the microkernel, the GPUI desktop, the browser engine, the editor, the chat system, and 34 applications in a single, interlocked monorepo, build friction and dependency cascades eventually choked developer iteration.

The diaspora to delvetalk2, minidregg, spween, and obend-gui was a necessary retreat to sanity—a subtraction campaign that restored fast cycles, modular boundaries, and clean formal methods. Now that minidregg has settled the verified kernel core, obend has established the projection viewports, and delvetalk2 has proven the power of an inhabited town of objects, the rich surfaces of DeOS and Starbridge can be reclaimed.

By re-attaching the moldable inspector, the rehydratable membrane, the 32 starbridge apps, and the card-based view-tree to these lean modern substrates, Ember's original 1999 AOL wonder—the live, malleable, self-describing computing image where a child can click with delight and an adept can inspect every mathematical invariant—is finally ready to live.

1.1 The game engine thesis: "Every move is a receipt"

As documented in project-game-engine-strategy.md:11-16:

"EVERY MOVE IS A RECEIPT. dregg is a verified game ENGINE, and the proof of that is a 3-game PORTFOLIO, not one game. A turn is a cap-gated transition the executor re-checks against constraints (StateConstraint teeth) and folds into a succinct verify_history-accepted proof. The architecture established an essential design law formulated by Ember:

"The architecture lesson that survived (ember's correction): a complex game's mechanics are a Custom VK / a Custom leaf, NOT StateConstraint teeth. Teeth are for simple state; a Custom AIR is for the transition." (project-game-engine-strategy.md:40-42).

1. What Lived in breadstuffs (The Monolithic Peak)

1.1. Federation, Consensus, and the Blocklace

The federation layer was designed to execute multi-node consensus with verified finality. Its primary documents were GOAL-FEDERATION.md and memory file project-federation-payoff.md.

The n=4 Federation Payoff (2026-07-07)

On 2026-07-07 (cv session 5d12f365-a748-4e7a-b4ca-99a0291fef49), Ember achieved the core federation milestone: a foreign, non-operator client signed its own transfer, submitted via POST /turns/submit, and it stream-finalized cross-node on a verified-executor $n=4$ mesh across two physical machines (hbox at 192.168.50.39 and nextop at 192.168.50.130). The test harness node/tests/payoff_client_turn.rs verified:

  • Dest account funded across all 4 nodes;
  • Block heights advanced uniformly: [1,1,1,1] → [2,2,2,2];
  • Finalized in ~25 seconds over two clean rounds under DREGG_TEST_REQUIRE_FINALITY=1.

The $O(\text{history})$ Wall in Verified Finality

The path to this payoff uncovered a severe architectural defect. When running with the verified Lean tau-order finality gate (VerifiedFinality::compute_order, node/src/finality_gate.rs:150 calling dregg_tau_order FFI into Lean's tauOrderFast), an $n=3$ node mesh would plateau while $n=4$ progressed. The investigation proved this was not a correctness fault, but a catastrophic complexity cliff:

*"The verified-Lean tau-order finality gate was $O(\text{history})$, recomputed from scratch on EVERY finality poll: the serial executor rebuilt the whole wire and Lean rebuilt PastCache/RoundCache over the full lace on each call, then discarded them. As the DAG grew, per-poll cost outpaced block production and the consensus stalled."* — project-federation-payoff.md

The Blocklace: Cordial Dissemination and Eviction-by-Past

The consensus engine in /Users/ember/dev/breadstuffs/blocklace/ implemented a Byzantine-repelling Directed Acyclic Graph (DAG) based on Almeida & Shapiro (2024, arXiv:2402.08068) and Cordial Miners (Shapiro et al., 2022, arXiv:2205.09174). In cv session ad7d9679 (sub-agent of 27b28e60, 2026-08-08, recorded in docs/reference/READING-BLOCKLACE-2026-08-08.md), Ember dispatched a literature review that uncovered a fundamental divergence between theory and implementation:

  1. The Live-Gossip Mutation Defect: The implementation in blocklace_sync.rs stated that the tau participant set must be a deterministic function of committed state alone. Yet handle_push called constitution.auto_evict(proof) on gossip arrival, mutating the live participant set. If Node A saw both halves of an equivocation fork and Node B saw only one, Node A ran at $n-1$ while Node B ran at $n$. Consequently, the wave leader formula wave_leader = participants[wave % n] selected different leaders on different nodes, creating a silent fork. Furthermore, because eviction was not a block in the DAG, a reboot silently reinstated the equivocator.
  1. The Fix (Commits 89238335a and 0eccd772d, 2026-08-08/09): Ember corrected this by moving eviction off gossip-arrival mutation into exclusion-by-past (node(b) ∉ byz(⌊b⌋)), making eviction a structural predicate over a block's causal closure:

Followed by commit 0eccd772d1348fb29b79658cf134f3fc18fcfe6d (Sun Aug 9 05:26:58 2026), adding 2,115 insertions across blocklace/src/constitution.rs and blocklace/src/finality.rs to enforce the Cordial Miners Alg. 1:5 two-tips-per-miner flood cap and CreatorTips::Pair evidence requirements.

  1. DFA-Federation: To prevent circular dependencies (cell -> dfa -> federation -> captp -> cell), /Users/ember/dev/breadstuffs/dfa-federation/ isolated route updates. FederationQcVerifier verified route transitions using a BLS ThresholdQC over old_commitment || new_commitment:

1.2. Distributed Object Capabilities: captp

The CapTP implementation in /Users/ember/dev/breadstuffs/captp/ provided capability transport across federations, combining the classic Agoric/E CapTP architecture with post-quantum cryptography.

Architecture and Invariants

Defined in captp/src/lib.rs:

The PQ Harness Pitfall

A critical test-suite bug plagued captp. In commits d2181916c and d78b8512b, Ember discovered that 130 tests across captp and related crates had never executed because dregg-pq aborted the process with process::abort() when the Lean-verified ML-DSA-65 cores were missing in test binaries, causing tests to exit prematurely with bare SIGABRTs.

       uint256 public constant BABYBEAR_P = 2013265921;
       IGroth16Verifier25 public immutable verifier;

       uint32[8] private _genesisLanes;
       uint32[8] private _provenLanes;

           uint32[8] calldata newRootLanes,
           uint64 numTurns,

1.4. Democratic Deliberation, Commons Governance, and Polisware

breadstuffs contained one of the most mathematically ambitious governance stacks ever designed, spanning game theory, Ostrom commons management, and formal social choice.

Collective Choice (collective-choice/src/lib.rs)

Composed four formal mechanisms into a unified VoteEngine:

  1. One-Vote-per-Ballot: Ballot cell with a WriteOnce(VOTE) constraint.
  2. Monotone Tally: Poll cells with Monotonic option tallies, preventing replay attacks from lowering counts.
  3. Quorum Gate: In-cell affine inequality constraint: $$\text{AffineLe} \{ M \cdot \text{RESOLVED} - \sum \text{TALLY}_i \le 0 \}$$
  4. Non-Amplifying Delegation (Liquid Democracy): Macaroon attenuation via Mandate::sub_delegate (DelegTree::no_amplify).
  5. One-Vote Nullifiers: Third layer of defense preventing double voting across the network.

The Commons Arbiter (commons-arbiter/src/lib.rs)

An "AI authority nobody owns" (docs/deos/UNCENSORABLE-UTILITY.md). An autonomous LLM evaluator governed by a community Rubric:

  • A member submits a Case (content + rubric ID).
  • An attested LLM session emits a ruling carrying a ZkOracleAttestation.
  • Anti-Prompt-Injection Proof: The attestation proves the ruling is authentic, well-formed JSON, and injection-free (proved free of {{ handlebars delimiters via a verified negative-regex matcher).
  • Quorum Ratification: A ruling becomes final only when a committee of $n$ independent operators ratifies it ($\lfloor 2n/3 \rfloor + 1$).

Grain Commons (grain-commons/src/lib.rs)

A decentralized app-store and execution commons for hosted AI agents (Sandstorm grains):

  • Signed .spk packages where the App ID is the author's Ed25519 public key.
  • Committed Umem memory heaps with tamper-proof Pedigree Merkle trees tracing every code fork.
  • GenesisAgent minting bounded child sub-agents with attenuated capability ceilings.

Polisware: The 66-File Lean Corpus (metatheory/Polis/)

Polisware was the formal mathematical constitution for multi-agent coexistence, synthesizing Ember's work on svenvs with computable politics. The spine is defined in metatheory/Polis/Polis.lean:

/-- **`polis_safety` — verify the cage, not the animal.** For a sound policy, a safe
shield, and a safe start, the enveloped system keeps the floor at EVERY step, for EVERY
controller. The controller is universally quantified and never inspected: no psychometric
classification of the inhabitant can be load-bearing for the guarantee. -/
theorem polis_safety
    {step : State → Action → State} {safe : Floor State}
    {pol : Policy State Action} {shield : State → Action} {init : State}
    (sound : SoundPolicy step safe pol)
    (shieldSafe : ∀ s, safe s → safe (step s (shield s)))
    (initSafe : safe init) :
    ∀ (ctrl : State → Action) (n : Nat),
      safe (traj step (envAct pol shield ctrl) init n) := by
  intro ctrl
  have step1 : ∀ s, safe s → safe (step s (envAct pol shield ctrl s)) := by
    intro s hs
    unfold envAct
    by_cases hp : pol s (ctrl s)
    · rw [if_pos hp]; exact sound s (ctrl s) hs hp
    · rw [if_neg hp]; exact shieldSafe s hs
  intro n
  induction n with
  | zero => exact initSafe
  | succ k ih => exact step1 _ ih
