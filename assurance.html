05A · Polyglot Proof Infrastructure

Five Running Formal Verification Substrates

Different layers of a verifiable compute stack demand different logical foundations: dependent type theory (Lean 4) excels at algebraic geometry and circuit metatheory; LCF-style HOL4/CakeML/Candle provides a verified path to bare-metal x86-64 machine code; ACL2 provides industrial bit-vector andJVM/ISA induction; and Isabelle/HOL exports ultra-fast SML/MLton decision binaries.

In ~/dev/svenvs and ~/dev/hol-reflection, we built a reflective HOL Light / Candle prover inside HOL4/CakeML. To overcome Löb’s Theorem (a consistent system $T$ cannot prove $\text{Sound}(T)$ without becoming inconsistent), `loebReductionScript.sml` splits the system into a frozen verified reference kernel $K_0$ and a dynamic tactic/compiler loop $P_k$, proving `prover_self_improvement_watchdog_concrete` and executing an in-place x86-64 binary self-upgrade (`cake-selfupgrade`, 1.19 GB ELF). In ~/dev/verifereum, we verify EVM bytecode and `Orb`’s 1,868-byte x86-64 dataplane in HOL4.

05C · Adversarial Verification

Anti-Vacuity Gates (`CarrierCensus.lean`) & Adversarial STARK Red-Teaming (`52e1fab`)

Lucid Computing emphasizes: “We run adversarial programs. The teams trying to break it are never the ones who built it.” In our ecosystem, adversarial red-teaming targets both formal specifications (catching vacuous theorems where a bug in definitions makes `False → anything` provable) and cryptographic provers (catching soundness bugs in recursive FRI).

Anti-Vacuity Gate`CarrierCensus.lean`

The `Fin (2^0) → Bool` Cantor Bug & `ApexPremiseVacuity.lean`

During a formal audit of `breadstuffs`, we discovered a subtle vacuity trap: a theorem quantified over `f : Fin (2^0) → Bool` and assumed `Function.Injective f`. Because $|\text{Fin}(1)| = 1$ and $|\text{Bool}| = 2$, that one-element case is inhabited, whereas for `Bool → Fin 1` injectivity is `False` by Cantor’s theorem—making any theorem assuming it vacuously true!

We built metatheory/Dregg2/ApexPremiseVacuity.lean and CarrierCensus.lean to enforce inhabited witness constructors (`Nonempty` / explicit trace witnesses) for every apex theorem, paired with ~/dev/forensics (automated git-DAG and transcript integrity auditing). See the live essay: Green Is Not True.

Plonky3 Red-Team`52e1fab` · Lean 4 Fix

The Recursive Plonky3 FRI Query-Index Collapse (`TwoRegimeQueryBudget.lean`)

In ~/dev/plonky3-recursion (commit 52e1fab), our red-team discovered that sorting and deduplicating sampled FRI query indices inside the recursive verifier circuit silently collapsed effective soundness when birthday collisions reduced the distinct query count below the target security threshold.

We formalized the exact collision distribution in TwoRegimeQueryBudget.lean, proved the two-regime query budget required to guarantee 128-bit security without variable-length circuit branching, and shipped the live visual postmortem: The Fix Is a Theorem.
