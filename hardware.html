inductive Run : Phase → Heap → Env → Expr → Heap → Val → Cost → Prop where
  | lit (H : Heap) (E : Env) (v : BaseVal) :
      Run .eval H E (.lit v) H (.base v) Cost.zero
  | knot_skip (H : Heap) (E : Env) (p : Expr) (a : Addr) :

      Run .eval H1 (a :: E) p H2 v c1 →

1.1 Substrate Integration (dregg-cell::tee_attest)

Inside the cell layer (cell/src/tee_attest.rs), hardware TEE attestation is integrated as a canonical WitnessedPredicateKind::Custom verifier keyed by the domain-separated verification key tee_predicate_vk():

pub const TEE_ATTEST_DOMAIN: &[u8] = b"dregg-tee-attestation-verifier-v1";

pub fn tee_predicate_vk() -> [u8; 32] {
    canonical_predicate_vk(TEE_ATTEST_DOMAIN)
}

Quotes from all supported hardware vendors share a 1-byte discriminant prefix (TeeQuoteKind) followed by the vendor-native attestation payload (encode_tee_proof, decode_tee_proof):

rust

#[repr(u8)]
pub enum TeeQuoteKind {
    SevSnp = 1,
    IntelTdx = 2,
    IntelSgx = 3,
    AwsNitro = 4,
}

TCB evaluation across platforms is normalized into TcbStatus and TeeReportClaims:

rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum TcbStatus {
    /// Platform exposes a TCB version and it meets the verifier's pinned minimum.
    MetPolicy,
    /// Platform exposes a TCB version and it falls below the verifier's pinned minimum.
    BelowPolicy,
    /// Platform's attestation document carries NO TCB-version rung (e.g. AWS Nitro).
    NoPolicyOnPlatform,
}

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct TeeReportClaims {
    /// 32-byte enclave image measurement (`MRENCLAVE`, `MRTD`, `MEASUREMENT`, or folded `PCR0..2`).
    pub measurement: [u8; 32],
    /// 32-byte user-supplied `report_data` bound into the hardware signature.
    pub report_data: [u8; 32],
    /// Platform TCB status relative to the verifier's pinned policy.
    pub tcb: TcbStatus,
}

TcbStatus::as_token() emits wire strings "met-pinned-minimum", "below-pinned-minimum", and "no-tcb-rung-on-this-platform"; TcbStatus::is_refusal() returns true iff matches!(self, Self::BelowPolicy).

The cell-layer predicate adapter TeeWitnessedPredicateVerifier is fail-closed by default (inner: Option<Arc<dyn TeeAttestationVerifier>> is None in TeeWitnessedPredicateVerifier::fail_closed()). When a concrete verifier is installed, TeeWitnessedPredicateVerifier::verify enforces four conditions:

  1. Decodes (kind, report_bytes) via decode_tee_proof(proof_bytes).
  2. Calls verifier.verify_report(kind, report_bytes) to validate the hardware vendor's cryptographic signature chain.
  3. Checks &claims.measurement == commitment (the cell's StateConstraint::Witnessed 32-byte commitment must equal the enclave's code measurement).
  4. Checks claims.report_data == Self::input_commitment(input)? (where PredicateInput::FieldElement(v) from grain_turn::ATTESTATION_SLOT is SHA-256 hashed via Sha256::digest(b"dregg-tee-field-input-v1:" || v.to_le_bytes()) or passed raw as PredicateInput::Bytes32) and !claims.tcb.is_refusal().

1.2 AWS Nitro Enclaves (NitroVerifier)

Implemented in tee-verify/src/lib.rs (introduced in commit 17b6e5539, 2026-07-11, hardened in commit a9d5df4db, 2026-09-30), NitroVerifier verifies AWS Nitro Hypervisor attestation documents without any external network calls:

  • Pinned Hardware Root of Trust: AWS_NITRO_ROOT_PEM embeds tee-verify/src/aws_nitro_root_g1.pem (CN=aws.nitro-enclaves, O=Amazon, C=US, valid 2019-10-28T13:22:05Z to 2049-10-28T14:22:05Z, P-384 public key, SHA-256 fingerprint 641a0321a3e244efe456463195d606317ed7cdcc3c1756e09893f3c68f79bb5b).
  • CBOR COSE_Sign1 & AttDoc Parsing:
  • CoseSign1 is deserialized via ciborium as a 4-tuple (ByteBuf, ciborium::Value, ByteBuf, ByteBuf) representing [protected, unprotected, payload, signature], optionally wrapped in CBOR tag 18. The signature length must be exactly 96 bytes (r || s, 48 bytes each for P-384).
  • AttDoc is deserialized from payload:
rust
    struct AttDoc {
        module_id: String,
        digest: String,
        timestamp: u64,
        pcrs: BTreeMap<u8, ByteBuf>,
        certificate: ByteBuf,
        cabundle: Vec<ByteBuf>,
        #[serde(default)]
        public_key: Option<ByteBuf>,
        #[serde(default)]
        user_data: Option<ByteBuf>,
        #[serde(default)]
        nonce: Option<ByteBuf>,
    }
  • Requires !doc.module_id.is_empty() and doc.digest == "SHA384".
  • X.509 Certificate Chain Verification (verify_cert_chain):
  • Parses pinned_root_der from AWS_NITRO_ROOT_PEM and asserts doc.cabundle[0].as_slice() == pinned_root_der.contents.as_slice() (byte-exact root match).
  • Constructs the full chain [cabundle[0], cabundle[1..], certificate] and parses every DER certificate via x509-parser.
  • Checks X.509 validity windows (cert.validity().is_valid_at(t)) at ref_time = doc.timestamp / 1000 (converting Nitro's millisecond timestamp to Unix seconds).
  • Verifies every parent→child link window[1].verify_signature(Some(window[0].public_key())).
  • ES384 COSE_Sign1 Signature Verification (verify_cose_sig):
  • Serializes RFC 8152 §4.4 Sig_structure = ["Signature1", protected, b"", payload] to CBOR bytes.
  • Extracts the leaf certificate's P-384 SEC1 public key (p384::ecdsa::VerifyingKey::from_sec1_bytes) and verifies the 96-byte ECDSA-P384/SHA-384 signature (p384::ecdsa::Signature::from_slice(sig_bytes)).
  • Measurement Folding & report_data Extraction:
  • fold_pcrs verifies that PCR0 (enclave image), PCR1 (Linux kernel + bootstrap), and PCR2 (application) are each present and 48 bytes (SHA-384), then folds them into a 32-byte commitment: $$\text{measurement} = \text{SHA-256}(\text{PCR}_0 \mathbin{\Vert} \text{PCR}_1 \mathbin{\Vert} \text{PCR}_2)$$
  • extract_report_data requires doc.user_data to be Some and at least 32 bytes; if doc.user_data is 32 bytes it copies it directly into claims.report_data (rejecting documents with missing user_data so an empty user_data can never collide with [0u8; 32]).
  • Sets claims.tcb = TcbStatus::NoPolicyOnPlatform because Nitro attestation documents do not expose a numeric TCB SPL vector.
  • Document Freshness Enforcement (check_nitro_freshness):
  • Added in commit a9d5df4db to close audit finding F10: fails closed if now_secs == 0, if doc.timestamp == 0, if doc_ts > now_secs + MAX_FUTURE_SKEW_SECS (60 seconds), or if now_secs - doc_ts > max_age_secs (default MAX_DOC_AGE_SECS = 3600).

3.1 The dark-fba/n4-k4-q15/v0 Model & price_tie_low Witness

  • QUANTITY_MAX = 15 (q_i ∈ 0..=15), so maximum single-side aggregate quantity is MAX_SIDE_TOTAL = 4 * 15 = 60 (owner.rs:9).

  • Slot 2: padding Side::Buy, limit_tick = 0, quantity = 0
  • Slot 3: padding Side::Sell, limit_tick = 3, quantity = 0

3.2 What Each Participant Can Check Locally (owner::audit)

In a shielded / TEE-only dark pool without a validity proof, each participant $i$ sees only the public batch header (cleared_tick, volume, delivery_root, batch_digest) and their own private fill opening fill_i (with Merkle path to delivery_root). In experiments/shielded-baseline/src/owner.rs, each owner runs the strongest possible 8-point local audit (owner::audit):

  1. BatchDigestMismatch: header digest matches the committed order slots.
  2. PublicationInvalid: volume <= SLOT_COUNT * QUANTITY_MAX (60) and NoCross ==> volume == 0.
  3. InclusionFailed: Merkle inclusion proof of (slot, owner_id, fill_i, salt_i) against delivery_root.
  4. Overfill: fill_i <= order.quantity.
  5. BelowMinimum: fill_i == 0 || fill_i >= order.min_fill.
  6. VolumeBelowFill: fill_i <= header.volume (since a single participant's fill cannot exceed total cleared volume).
  7. CrossedWithoutFill: if header.cleared_tick == NoCross, fill_i == 0; if Tick(p) is worse than order.limit_tick, fill_i == 0.
  8. ProRataImplausible (pro_rata_feasible): if the order is eligible at Tick(p), checks whether there exists any hypothetical aggregate side total $T \in [\max(q_i, V), 60]$ and hypothetical pre-OrderId-tiebreak prefix $B \in [0, \min(\text{slot}, (V \cdot T) \bmod T)]$ such that integer pro-rata rationing $\lfloor \frac{V \cdot q_i}{T} \rfloor + \mathbb{I}[\text{tiebreak}]$ produces fill_i.

3.3 The Exhaustive Forgery Theorem: 377 out of 1,125 Outcomes Survive

In exhaust_price_tie_low_forgeries, the test enumerates the entire candidate outcome space for price_tie_low():

  • $5$ cleared-tick values (NoCross, Tick(0), Tick(1), Tick(2), Tick(3))
  • $9$ volume values ($V \in 0..=8$, where $8 = \sum q_i$)
  • $5$ fill values for Buyer 0 ($f_0 \in 0..=4$)
  • $5$ fill values for Seller 1 ($f_1 \in 0..=4$)
  • $1$ fill value for Padding 2 ($f_2 = 0$) and $1$ fill value for Padding 3 ($f_3 = 0$)
