04C · Defense-in-Depth

Why TEEs Alone Are Insufficient (`residual_trust.rs`) & Bare-Metal `seL4` Microkit

A central question for any verifiable compute architect is: “Why do we need Merkleization and STARKs if we already have a hardware TEE?” We answered this with an executable theorem-backed test suite (`residual_trust.rs`) and a bare-metal `seL4` Microkit architecture.

377 / 1,125 Forgery Proof`residual_trust.rs`

The TEE Residual-Trust Boundary Proof

In degg-research/experiments/tee-residual-trust/src/residual_trust.rs, we exhaustively enumerate 1,125 execution scenarios across a malicious host controlling untrusted DRAM/disk outside a TEE. Without STARK + MMR anchoring, a TEE-only receipt allows the host to forge 377 of 1,125 scenarios (33.5%) via stale-state replay, cross-epoch splicing, and selective turn omission. Adding the STARK + MMR state-continuity invariant reduces undetected host forgery from 377 to 0.
